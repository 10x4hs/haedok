고른 기술과 이유

더 좋아 보이는 것보다, 이 크기의 앱에 맞는 것을 골랐어요. 대신 치른 값도 같이 적었어요.

고른 것왜안 고른 것치른 값
FastAPI (async)DB·메일·책 API를 기다리는 동안 다른 요청을 처리해요. 로그인·DB 세션은 Depends로 함수에 넣어 줘요.Django — 관리 화면까지 딸려 와 이 크기엔 커요.화면 쪽 도구는 직접 골라야 해요.
Jinja2 + 바닐라 JS첫 화면이 HTML로 바로 와요. JS가 {{ "{:,}".format(facts.js_lines) }}줄이라 프레임워크 없이 충분하고, 빌드가 없어요.React·Next.js — 노드 빌드와 API를 따로 관리해야 해요.화면 상태는 손으로 맞춰요.
PostgreSQL + SQLAlchemy 2unique 제약과 트랜잭션이 규칙의 일부예요. 같은 마일리지를 두 번 주지 않는 것도 unique 제약이 지켜요.SQLite만 쓰기 — 서버리스에서는 파일이 오래 남지 않아요.쿼리를 직접 다듬어야 해요.
Vercel 파이썬 함수서버를 계속 켜 두지 않아도 요청이 올 때만 돌아요.늘 켜진 서버 — 아무도 안 쓸 때도 비용이 들어요.실시간은 소켓 대신 폴링이고, 요청 본문이 4.5MB에서 끊겨 배포에서는 업로드 크기를 작게 둬요.
pytest + GitHub Actions규칙이 깨지면 머지 전에 실패해요. 마이그레이션은 진짜 Postgres에서 올렸다 내렸다 다시 올려 봐요.손으로 눌러 보며 확인하기기능마다 테스트를 같이 써요.

고민한 결정 네 가지

고른 방법만큼 버린 방법이 중요했어요. 다음에 고치고 싶은 점도 남겨 둬요.

읽은 시간은 서버가 재요

고른 방법

  • 펼친 시각과 ‘다 읽음’ 시각을 둘 다 서버가 적어요. 화면은 시간을 보내지 않아요.
  • 바로 다음 쪽만 판정하고, 남는 시간은 {{ facts.cap_x }}배까지만 기록해요.

고르지 않은 방법

화면이 잰 시간 받기
개발자 도구로 ‘20초 읽음’을 보내면 끝이에요.
이해도 퀴즈
책마다 문제를 만들어야 하고, 직접 올린 파일에는 만들 수 없어요.

다음에는 고정 {{ facts.page_s }}초 대신 쪽의 글자 수에 맞춰 보고 싶어요. 지금은 판정 때 쪽 본문을 읽어 오지만 쓰지 않아요.

스포일러는 서버가 가려요

고른 방법

  • 응답을 만들 때 가려요. 아직 안 읽은 쪽이면 응답 안에 감상 본문이 아예 없어요.
  • 기준은 DB에 있는 내 진도예요. 화면이 보낸 값은 쓰지 않아요.
  • 개수는 알려 줘요. ‘🔒 3개’가 다음 쪽을 읽게 해요.

고르지 않은 방법

화면에서 흐리게 가리기
응답을 열어 보면 본문이 그대로 있어요.
실시간 알림에 본문 싣기
가드를 거치지 않는 길이 하나 더 생겨요.

다음에는 쪽마다 도는 쿼리 세 번(같은 방 사람, 감상, 내 진도)을 하나로 줄이고 싶어요.

실시간은 폴링으로

고른 방법

  • 배포에서는 리더가 3초마다 친구 위치를 물어봐요. 서버가 여러 대여도 빠지는 소식이 없어요.
  • 탭이 가려지면 멈춰요. 안 보는 화면은 요청하지 않아요.

고르지 않은 방법

WebSocket + 서버 메모리
서버가 여러 대면 다른 서버에 붙은 친구에게 소식이 안 가요. 실제로 겪은 문제예요.
Redis 같은 공유 브로커
방 하나에 많아야 {{ facts.max_members }}명인 지금 크기에는 비용과 운영이 과해요.

가입 코드는 지문으로만

고른 방법

  • {{ facts.code_digits }}자리 코드는 서버 비밀키를 섞은 HMAC 지문으로만 저장해요. DB가 새도 코드를 알 수 없어요.
  • 만료({{ facts.code_min }}분)와 횟수({{ facts.code_attempts }}번)를 비교보다 먼저 확인하고, 비교는 compare_digest로 해서 걸린 시간으로 정답이 새지 않아요.

고르지 않은 방법

bcrypt 같은 느린 해시
{{ facts.code_digits }}자리는 경우의 수가 적어 느려도 금방 다 해 봐요. 비밀키를 섞는 HMAC이 맞아요.
메일 속 링크로 인증
메일 앱이 다른 브라우저로 열면 가입하던 화면과 이어지지 않아요.

다음에는 틀린 횟수를 ‘읽고 더해서 쓰기’ 대신 UPDATE 한 문장으로 올리고 싶어요. 동시에 두 번 틀려도 정확히 세요.

http://localhost:8011을 열어요. DWELL_SCALE=0.06은 쪽마다 {{ facts.base_page_s }}초를 {{ "%g"|format(facts.base_page_s * 0.06) }}초로 줄여서 시연하기 편해요. API 문서(Swagger)는 /api/docs에 있어요.
